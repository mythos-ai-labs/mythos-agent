# Mythos 产品与技术设计

本文档集将 [项目目标](../goal.md) 中的创作原理转化为产品概念、领域模型、系统架构和技术选型依据。面向产品设计者、架构设计者及后续开发者，当前交付是设计文档，不是已实现产品的使用说明。

编写与资料核查日期：2026-09-28。范围：概念设计与选型论证。原始材料 [goal.md](../goal.md) 保持原样；其中的学习顺序用于组织领域理解，不作为必须逐课完成才能设计产品的限制。

## 1. 决策状态

| 标记 | 含义 | 使用规则 |
| --- | --- | --- |
| 用户已确定 | 本次需求与澄清中确认的方向 | 后续设计遵循；改变时应说明影响 |
| 设计建议 | 文档提出的产品或技术方案 | 可作为详细设计起点，不等于用户逐项确认或已完成验证 |
| 待验证假设 | 需要技术试验或用户试用检验的判断 | 指向验证方法与失败后的处理方向 |

**用户已确定**：个人本地 Web 工作台；通用 Agent 平台；小说为首个预置应用；作者主导；自有 Harness 并复用 SDK；优先 TypeScript 全栈；多供应商且用户自带密钥；本轮只产出概念设计与选型论证。

**设计建议**：Windows 本地运行优先；单用户、单本地服务；React + Vite、Node.js + Fastify、SQLite + Drizzle、AI SDK 作为基线；通用运行底座通过应用扩展承载小说功能；正式内容通过版本化变更提案更新。

**待验证假设**：轻量自有 Harness 的恢复能力、中文全文检索的召回、长文编辑性能、跨模型工具调用质量及作者审阅负担。验证安排见 [路线与验证](07-roadmap-validation.md)。

## 3. 共同术语

| 术语 | 本项目含义 |
| --- | --- |
| Harness | 包围模型的运行机制：循环、上下文、工具执行、权限、状态、预算与恢复 |
| 工作空间 Workspace | 一组相关资料、会话、产物、应用配置的隔离边界；一本小说通常对应一个工作空间 |
| 会话 Session / 任务 Task / 运行 Run | 会话承载交流；任务表达目标与完成条件；运行是一次具体执行，恢复或重试有可追溯记录 |
| Agent 配置 | 职责说明、模型选择、可用工具、Skill 与执行约束的组合 |
| 产物 Artifact | 可以独立审阅和版本化的文档、计划、正文或其他输出，不等同于聊天消息 |
| 变更提案 Change Proposal | 基于明确版本的候选修改及其影响，批准后才能更新受保护的正式内容 |
| Canon | 作者已确认且在指定版本中有效的事实、规则或叙事约束；不等于所有生成文本 |
| Anchor | 作者明确锁定的创作意图或边界，例如某个秘密不得提前揭露；可由作者显式修订 |
| 世界时间线 / 叙述时间线 | 事件实际发生顺序 / 读者在正文中接触信息的顺序 |
| 检查点 Checkpoint | 已持久化的执行进度与恢复依据，不代表一次业务变更已提交 |
| 回放 / 重试 / 恢复 | 查看历史记录 / 发起新的执行尝试 / 从已核实的执行边界继续，三者不能混称 |
| Commit | 将经确认的正文与相关事实作为一致的业务版本提交；不是 Git commit |

## 5. 全文共同边界

- 本地存储不等于完全离线：云端模型会接收本次选择的上下文，界面应让用户看清供应商与资料范围。
- 通用权限控制与作者的内容决定权分开：允许生成草稿不等于批准更新 Canon。
- 以已确认的业务版本为事实来源；摘要、索引、模型判断均不能悄悄覆盖它。
- 系统承诺保留来源、版本和执行证据；文学生动性、因果合理性等需要作者判断，不宣称自动证明。
- 全文中的能力、性能和验收阈值均是未来产品目标，除明确记录的文档检查外，不表示完成了运行验证。
