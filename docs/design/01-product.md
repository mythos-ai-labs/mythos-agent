# 产品需求与定位

[返回导航](README.md) · 领域依据：[小说领域](02-domain.md) · 交互方案：[UI/UX](06-ui-ux.md)

## 1. 决策状态与产品主张

**用户已确定**：个人本地 Web、通用 Agent 平台、小说为首个应用、作者主导、多供应商自带密钥、TypeScript 优先、自有 Harness。当前只设计产品与技术方向。

**设计建议**：Mythos 是一个围绕工作空间与可审阅产物组织任务的 Agent 工作台。小说应用帮助作者把“人物为何这样选择、选择改变了什么”持续落实到正文与故事状态。平台同时能完成资料整理等非小说任务。

**待验证假设**：目标用户愿意为一致性与控制力接受适量结构化输入；场景级提案比逐条确认每个事实更容易使用；通用入口不会增加作者的认知负担。验证见 [路线与验证](07-roadmap-validation.md)。

## 2. 用户、问题与成功表现

| 用户 | 当前问题 | 期望结果 |
| --- | --- | --- |
| 独立长篇作者，核心用户 | 对话越长，人物动机、知识边界、物品与伏笔越难维护 | 写完场景能看到“正文改了什么、故事状态改了什么”，修改可追踪 |
| 构思型作者 | 设定很多，但人物缺少行动理由 | 从六问种子推演可选择的冲突与后果，而非堆积名词 |
| 使用 Agent 的个人研究者 | 文件、聊天和输出分散，重复整理难以接续 | 配置资料助手，得到带来源的产物，中断后可继续审阅 |
| 有技术能力的个人用户 | 希望组合模型、工具与提示，但不愿从零写运行底座 | 配置 Agent、接入工具和本地应用扩展，复用执行与审阅机制 |

产品成功首先体现为：用户可以完成一次有明确目标的任务，理解依据，修订或拒绝结果，重启后继续工作。模型说“完成了”不构成完成标准；小说正文可读性和角色可信度需要独立评审。

## 3. 核心场景

### 3.1 贯穿示例：林烬在废弃车站交换地图

本例用于设计推演，是从原始目标延展的示例，不是用户已确认的小说设定。规范版本见 [领域文档](02-domain.md)。

世界规定十八岁觉醒，失败者遭流放；林烬还有三天成年，想寻找三年前失踪的哥哥。车站场景中，林烬想从顾清手中取得地图，顾清想验证他是否可信。作者要求：林烬拿到地图，双方暂时合作，顾清察觉他隐瞒身份，但不能知道具体身份。

用户旅程：填写种子与创作边界 → 选择场景目标 → 比较两种行动方案 → 生成草稿 → 查看人物、关系、知识与物品变化 → 修改并确认整个场景提案 → 将地图线索带入下一场景。

可观察结果：批准前正式内容保持原版本；批准后正文与状态变化相符；“顾清怀疑林烬”不会被压缩成“顾清知道林烬身份”。

### 3.2 通用示例：旅行资料整理

用户导入三份自己的旅行笔记，创建“资料助手”，要求仅根据这些笔记整理地点清单，标出相互冲突的信息，不浏览外网、不改源文件。

Agent 在授权资料内检索，生成带来源位置的汇总产物；用户修正分类后确认版本。系统可以复用工作空间、任务、模型适配、工具、提案和回放，无需创建人物、世界时间线或 Canon。此示例只是抽象验证，不承担最新旅行建议或预订服务。

## 4. 功能需求与优先级

P0 是未来首个闭环目标；P1 扩展长篇与平台能力；P2 是有证据再投入的演进项。优先级不等于本轮实现承诺。

| 编号 | 能力 | 阶段 | 可观察的验收意图 |
| --- | --- | --- | --- |
| PR-01 | 本地工作空间、小说/通用模板、资料导入 | P0 | 明确数据位置；工作空间之间不串用上下文；先支持 TXT、Markdown |
| PR-02 | 供应商配置、模型能力与密钥管理 | P0 | 用户选择供应商；连接失败有原因；不把密钥写入作品或日志 |
| PR-03 | 会话、任务目标、计划、运行进度 | P0 | 看清在做什么、引用什么、当前是否需要用户操作 |
| PR-04 | 工具权限、预算、中断与恢复 | P0 | 拒绝或停止后不继续派发新操作；可核查已发生的操作 |
| PR-05 | 产物编辑、候选版本、提案审阅 | P0 | 草稿与正式版本分开；支持修改、拒绝及显式确认 |
| PR-06 | Agent 配置与内置能力组合 | P0 | 用户配置职责、模型、已注册工具、提示资源；无需开发新前端 |
| PR-07 | 六问种子、规则与人物动机 | P0 | 可解释目标、阻碍、失败代价和核心未知；支持留空后渐进补全 |
| PR-08 | 故事线、卷/章/场景组织、场景计划 | P0 | 每个场景有意图、选择与变化；故事线围绕问题演化 |
| PR-09 | 正文生成、手工编辑、校验与提交 | P0 | 所有通往正式正文的路径都经过一致性处理，手工修改也可追踪 |
| PR-10 | 双时间线、角色知识、Canon 与 Anchor | P0 | 简单视图可表达倒叙和揭露限制；禁止把未来知识带入过去视角 |
| PR-11 | 本地来源检索、导出与备份恢复 | P0 | 检索结果可回源；TXT/Markdown 导出与完整备份区分 |
| PR-12 | MCP 接入、本地扩展管理、受限子任务 | P1 | 扩展显式启用、可停用；工具和子任务继承收紧后的权限与预算 |
| PR-13 | 跨章改动影响、伏笔追踪、关系与时间线视图 | P1 | 能列出待复核章节和相关证据，不自动重写整部小说 |
| PR-14 | 长篇节奏与跨卷规划 | P1 | 查看问题推进、高潮分布、伏笔回收；作者可否定模型意见 |
| PR-15 | 向量检索、复杂图查询、经验反思 | P2 | 通过对照评估后再启用；不自动提升旧经验为新规则 |
| PR-16 | 可视化工作流编辑器、插件市场 | P2 | 建立在已验证的扩展契约之上，不作为首次使用的前置条件 |

平台定位允许更多领域应用，但首轮设计不扩张为全功能编程 IDE、浏览器自动操作平台或所有文档格式处理器。通用文件读写、Shell 与外部网络工具是未来可启用的工具类别，不因“通用”而默认获得全部权限。

## 5. 作者控制与质量约束

作者可以先讨论、再生成，也可以直接请求一份草稿。用户不必为只读检索和已授权的草稿生成反复点击确认。需要明确区分：工具能否执行、候选内容能否进入正式作品。

正式设定的硬矛盾、提案基础版本过期属于必须处理的问题；人物动机不足、节奏平淡属于可解释的编辑意见。若作者有意改变规则，应创建规则修订及影响复核，不使用一个泛化的“忽略全部”绕过一致性管理。

自动保存保存的是当前编辑草稿；“确认场景”才提交正文与相关状态。模型生成结果与作者正在输入的草稿分开存放，避免流式输出覆盖人工修改。

## 6. 非功能需求

| 维度 | 设计目标 | 检验办法 |
| --- | --- | --- |
| 数据可靠性 | 已确认的作品版本可恢复；提案提交不出现正文与 Canon 半更新 | 故障注入、磁盘写入失败与备份恢复演练 |
| 长期执行 | 关闭浏览器不等于取消；服务退出后可辨别可恢复、待核实和终止状态 | 断开连接、重启服务的场景测试 |
| 本地隐私 | 默认只监听本机；云推理仅发送已选上下文；密钥不进入产物 | 数据流与脱敏检查 |
| 成本控制 | 展示用量、预算与费用估算；预算不足前不启动新步骤 | 使用固定响应测试预算；真实价格缺失时显示未知 |
| 性能体验 | 长文输入不卡顿，进度可见；模型等待与本地响应分开衡量 | 代表性中文长文和运行日志负载测试 |
| 可维护性 | 小说应用可替换；模型 SDK 升级不改变平台核心概念 | 用通用示例和替代模型适配器检验边界 |
| 可访问性 | 键盘可达、焦点清楚、状态不只靠颜色 | 键盘走查及浏览器自动检查 |
| 数据可携带 | 正文可导出，完整作品及版本有独立备份；不依赖云账号才能读本地内容 | 无网络启动与恢复演练 |

首轮性能试验建议样本为 100 万中文字作品、1 万条事实/事件和 100 个场景草稿；记录硬件、模型和样本构造，测量后再制定 SLA。这是负载目标，不是已支持上限。

## 7. 范围边界与后续输入

本轮产出上述需求及设计论证，不包含原型代码、服务启动或真实模型调用。首个本地版本不包含账号体系、商业化、多租户、云同步、实时协作、自动发布、内容平台爬取和模型训练。

详细设计阶段需要补齐：任务和版本的状态定义、持久化迁移方案、接口契约、供应商能力测试集、Windows 安装与升级路径、凭据存储实现及故障恢复协议。具体模型名单与版本通过能力验证确定，不以“所有模型都兼容”作为承诺。
